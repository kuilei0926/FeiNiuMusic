## 2. 目标与范围

解决首页播放按钮过于抢眼、快捷入口沉重、迷你播放器与底部导航两个长条堆叠的问题。提供 C1 左置融合单岛、C2 中置对称黑胶岛、C3 悬浮微黑胶加无框导航三种形态，在“设置 → 应用外观 → 导航布局”中实时切换并持久化。黑胶展开为播放抽屉，完整播放页仍可进入。

首期改造手机布局的首页内容及共用底栏，因此歌单、歌曲、收藏、我的等主页面也会使用同一底栏。二级页面按现有能力声明决定显示播放区、导航区或隐藏全部。平板、桌面和 TV 继续使用侧栏与既有迷你播放器；首页共享组件的视觉调整须保留其缩放、焦点与可读性。

不更换播放引擎、不改服务端 API、漫游补链、队列上限、缓存及加载策略、不引入 React/Tailwind 或新的状态管理框架。完整播放页、系统媒体通知、DLNA 和歌词服务继续作为现有能力复用。

## 4. 原型差异与拟采用的决策

以下四项已获评审确认，作为实施约束；对应 UI 与导航将在后续阶段接入。

### 4.1 导航数量与稳定映射

PDF 前半段描述保留五个入口，但 TSX 明确为 C1/C2 去掉“歌曲”，C3 保留五个。建议遵循 TSX 的实际视觉设计：C1/C2 展示 `[0, 1, 3, 4]`，C3 展示 `[0, 1, 2, 3, 4]`；底层仍保留五个页面及原索引，不能把视觉位置 2 直接当作歌曲页索引。

“歌曲”在 C1/C2 下仍可通过首页“歌曲”快捷入口、“最新歌曲 → 查看全部”与侧栏等既有入口访问。若当前页面索引是 2，四入口底栏不错误高亮其他项目，页面标题明确显示“歌曲”；切到 C3 后应高亮“歌曲”。隐藏歌曲页的返回行为按第 14.1 节补充规则执行。设置预览必须提示：“C1/C2 极简模式下，歌曲库可从首页快捷入口或最新歌曲查看全部进入”。

若评审要求三种样式都常驻五个入口，需要重新确认 C1 的信息压缩和 C2 的对称构图，不应实现过程中静默删除导航功能。

### 4.2 点击行为统一

TSX 的 C2 点击黑胶会播放/暂停，而 PDF 倾向点击黑胶展开详情。建议三种样式统一为：黑胶或曲名打开抽屉；明确的播放键控制播放/暂停。C2 在曲名浮标旁安排独立播放键，下一首放入抽屉，避免一处点击承担两种语义。

TSX 的列表按钮只是打开或关闭演示抽屉；落地时必须进入真实队列。原型的收藏、循环、进度和歌词中存在模拟或无操作内容，全部对接现有服务，不保留演示占位功能。

### 4.3 默认值、兼容与回退

建议新安装缺省为 C1；升级且没有新设置键的老用户保留现有底栏，主动选择后再切换。设置中提供“现有样式”作为兼容和回退选项，另列三种黑胶样式。未知持久化值回退现有样式并保留原始值，避免覆盖未来版本的设置。该迁移策略已确认；首次迁移的保守判定见第 14.5 节。

样式只在手机布局生效；抽屉导航下保留抽屉入口，黑胶样式仅应用于迷你播放区，不新增一排导航。大屏可以保存选择，但说明“手机布局下生效”。

## 5. 三种底栏规格

尺寸为首版设计起点，单位均为 Flutter 逻辑像素。最终以可点击、可读、内容不遮挡为验收依据，不能直接照搬 CSS 像素。

| 样式 | 构成 | 首版尺寸建议 | 布局约束 |
| --- | --- | --- | --- |
| C1 左置融合单岛 | 左侧黑胶/曲名、中间环形进度播放键、右侧四入口；选中项空间允许时展开文字 | 主体 62dp，左右边距 12–16dp，底部间距 12dp | 宽度不足先隐藏歌手/曲名，再收起选中标签，保证按钮命中区；极窄窗口回退 C3 |
| C2 中置对称黑胶岛 | 两侧各两个导航；中央凸起黑胶和进度环；上方曲名浮标带播放键 | 主体 60–64dp，黑胶外环约 64dp；总高度按凸起、浮标及间距计算 | 宿主真实高度覆盖浮标和黑胶，保证凸出部分可命中；不只给 60dp 父盒再靠越界绘制 |
| C3 悬浮微黑胶 | 上方偏左短播放胶囊和独立队列键；下方五入口无框导航 | 微胶囊至少 48dp，行间距约 8dp，导航约 56dp，安全区另计 | 短胶囊优先曲名与播放；下一首在空间足够时保留，空间不足进入抽屉 |

C3 本身仍有两行，其改进是短胶囊、无框导航与视觉减重；不承诺三种样式都压缩至 62dp，也不采用原型“节省 55%”作为既成结果。

所有主要操作命中区域至少 48×48dp；视觉图标可更小，命中区不得交叠。320/360/390/430dp 与字体 1.0/1.3/2.0 倍是最低验证矩阵。大字体时允许宿主增高或回退 C3，并显示实际生效样式，保存的用户偏好不被覆盖。

## 6. 底部宿主与页面占位

### 6.1 建议组件职责

- `BottomIslandHost`：唯一底部入口，接收样式、目的地列表、当前索引、导航回调与页面显示能力；负责选择 C1/C2/C3/旧样式和响应式回退。
- `BottomIslandLayout`：集中计算布局规格与占位，输入可用宽度、文字缩放、安全区、键盘、是否有导航/歌曲、隐藏状态；输出实际样式和总占位。是绘制与滚动留白的同一事实来源。
- `BottomChromeScope`：向页面提供当前占位、宿主是否托管播放区等信息。`AppPageScaffold` 可继续通过旧入口使用该指标，迁移调用方时不散落新魔法数字。
- `VinylDisc`、`PlaybackProgressRing`、`IslandNavigationItem`：只管理视觉与点击，播放状态由现有服务传入；三种布局共享控件和行为。
- `VinylPlayerSheet`：可伸缩播放抽屉，不持有独立队列或播放器。

以上为计划名称，实施时允许按附近代码命名调整，不能改变职责边界。

### 6.2 所有权与隐藏规则

| 场景 | 所有者 | 建议行为 |
| --- | --- | --- |
| 手机五个主页面 | `_PrimaryNavigationShell` | 一份共享宿主，页面内不再额外渲染迷你播放器 |
| 手机二级路由 | `AppPageScaffold` | 读取页面能力声明；有导航用组合样式，无导航用同材质迷你播放区 |
| 手机抽屉导航 | `AppPageScaffold` | 抽屉导航继续存在，仅升级播放区 |
| 平板/桌面/TV | `TabletLayoutHost` | 继续使用既有大屏底部控件，手机宿主不挂载 |
| 多选 | 当前可见页面/共享 shell | 隐藏全部播放与导航区域，为多选操作栏保留占位；返回先退出多选 |
| 设置/完整播放/登录等显式隐藏页面 | 页面能力声明 | 尊重 `showMiniPlayer`、`hideBottomNav`，可只显示导航或完全隐藏 |
| 模态抽屉/队列 | 对应 Navigator 模态路由 | 遮罩拦截底层点击，避免透过遮罩切换 Tab；大屏沿用模态信号 |
| 输入法弹出 | 活跃页面能力及键盘状态 | 默认隐藏悬浮宿主；需固定控件的页面沿用现有显式参数语义 |

不能直接把 `miniPlayerSuppressedCount` 当作手机 shell 的唯一显示依据：`IndexedStack` 预热页面长期挂载，隐藏页面的声明不应永久抑制当前页面底栏。需通过 `PrimaryNavigationScope.currentIndex` 和活跃路由解析当前能力；保留现有大屏计数约定，增加针对预热与切页的回归测试。

### 6.3 占位计算

总占位 = 当前样式完整可交互包络高度 + 外侧底部间距 + 尚未被父层消费的底部安全区。列表另加内容尾部间距，安全区只能计算一次。C2 包络包括浮标，C3 包括两行。

首页替换固定 160dp；审计各页面 `scrollableBottomPadding` 和手写底部 padding，分清大屏、无导航、无歌曲、隐藏播放区等情况。样式切换期间预留新旧高度最大值，结束后收敛，避免最后一首歌曲被动画中的底栏盖住。底部最后一项及其更多按钮必须可完全滚出并点击。

## 7. 播放抽屉与真实状态

使用 `showModalBottomSheet` 配合可滚动/可拖动内容，初始高度约屏幕 60%–70%，可扩展以容纳大字体与小屏。抽屉内容包括黑胶和唱臂、曲名/歌手、当前歌词行、收藏、进度、播放模式、上一首、播放/暂停、下一首、队列与“打开完整播放页”。

| 功能 | 真实来源/操作 | 边界 |
| --- | --- | --- |
| 当前歌曲与封面 | `PlayerService.currentSong`、现有封面组件/缓存 | 无封面显示占位，不为视觉重复请求原图 |
| 播放/缓冲/进度 | `snapshot` 或已有对应 notifier | 进度和播放键局部重建，不让全首页跟随进度刷新 |
| 播放控制 | `togglePlayPause()`、`previous()`、`next()` | 继续遵守既有漫游、转码、投屏与队列逻辑 |
| 拖拽进度 | `seek(Duration)` | 拖动时本地预览，结束提交；绑定歌曲 ID，切歌后取消旧拖动；时长未知/不可 seek 时禁用 |
| 歌词 | `LyricsService.instance.currentLineText` 等现有状态 | 无歌词显示明确空态，不生成示例歌词 |
| 收藏/模式 | 复用现有收藏组件及播放模式操作 | 异步失败提供反馈，快速点击避免重复提交 |
| 队列 | `showPlayerPlaylistSheet(context, player)` | 先关闭抽屉再打开队列，避免嵌套 sheet 的关闭与遮罩混乱 |
| 完整播放页 | 现有 PlayerPage 路由构建方式 | 先关闭抽屉，再用仍有效的宿主 context 导航，保留返回来源 |

无当前歌曲时导航保持可用，播放区显示“选择歌曲开始播放”，禁用控制与空抽屉入口。播放完成、加载中、暂停、失效链接、投屏状态按现有状态显示。进度总时长为 null/零时显示不确定状态，比例始终限制在 0–1，不能用定时器模拟推进。

抽屉用一个展示中标记防重复打开；遮罩点击、向下拖动、系统返回均只关闭抽屉。任何模态状态置位必须在 `try/finally` 复位，异步后检查 `mounted`。弹层不写入完整播放页的 `playerRouteActive`。

## 8. 设置与数据兼容

建议新增 `settings_bottom_island_state.dart`，沿用 `ValueNotifier + SharedPreferences + ensureLoaded()`，通过 `settings_state.dart` 导出，在 `main.dart` 首帧前加载。与现有 `PlayerStyleSettings` 独立。

- 偏好键建议 `setting_bottom_island_style_v1`，值使用稳定字符串 `legacy` / `c1` / `c2` / `c3`，不保存枚举序号。
- `ensureLoaded()` 合并重复调用；读取失败安全回退并在 debug 下记录。设置写入采用串行或最后一次选择优先，防快速切换后旧值覆盖新值；失败反馈且保证当前选择和磁盘状态一致。
- 缺失键按第 14.5 节处理：在启动写入发生前，空偏好库初始化 C1，已有偏好初始化 legacy；引导标记不能单独作为新安装依据。
- 设置卡片预览复用实际绘制组件，使用静态样本、不连播放器、不启动旋转或网络；显示选中态、导航数量及适用布局说明。
- 保存时不重建整个 App、Navigator 或播放服务；切换约 200–300ms 淡入/位移，旧组件退出期间关闭交互和重复语义节点，受“减少动态效果”控制。
- 新键在通用备份排除名单外，验证备份/恢复往返；沿用既有恢复生效时机。若要求恢复后立即应用，应显式加入对应状态重载，不能仅写磁盘假定 notifier 自动更新。

## 9. 首页视觉改造

保留模块顺序和真实文案：推荐/漫游 → 歌曲、歌手、专辑、风格 → 最近播放/收藏 → 我的歌单 → 最新歌曲 → 最新专辑。保留分模块加载、错误重试、刷新入口和歌曲详情菜单。

1. Hero、最近播放和收藏的纯白圆形播放按钮统一为轻薄半透明按钮，取主题色与封面环境色，减少大面积纯白；保留独立播放回调、点击反馈和至少 48dp 命中区域。
2. 快捷入口增加低对比度图标槽、轻描边及柔和背景，图标/文字遵循主题。复用既有 Material、焦点和 TV 缩放，不机械复制 CSS 多层 blur。
3. 卡片边框和阴影统一使用现有视觉主题；优先修正局部强对比，不全局修改 `GlassPanel` 影响设置及其他页面。
4. 列表和封面沿用现有布局、缓存与播放来源；样式选择和歌曲进度变化都不重新调用 `_loadAll()`。

## 10. 材质、动画与性能

液体玻璃开启时复用 `GlassGate` 与现有玻璃参数；关闭时跟随 `panelBlurEnabled/panelBlurStrength` 或实色回退。PDF 中固定 blur=24 和纯黑背景只作视觉参考，不覆盖用户设置。浅色/深色、自定义背景、高对比下，颜色优先来自 `Theme.colorScheme` 和已有视觉主题。

黑胶用 `SweepGradient`、少量同心圆和封面组成；旋转周期约 9 秒。暂停调用 stop 保留角度，恢复继续；离开可见区域、App 后台、减少动态效果时停止 ticker，dispose 控制器。静态纹理与动态进度分层，限制模糊为底栏局部裁剪范围，避免多个动画玻璃层重复采样。

动态封面取色建议第二阶段再加入：先用主题强调色达到确定效果；若采用封面取色，优先复用缓存，以歌曲/封面版本作键，异步结果校验歌曲 ID，失败回退主题色，禁止逐帧取色。首期不新增依赖。

性能验收以同设备、同数据、profile 模式的新旧对照为准：录制播放时滚动首页、切 Tab、切样式、展开抽屉，检查帧耗时、重建和常驻 ticker。目标是在目标设备刷新周期内完成主要帧；如基线已超预算，先记录基线和新增开销，不能在未实测时声称“无性能影响”。

## 14. 二次评审补充约束

### 14.1 隐藏歌曲页返回

后续在 `_PrimaryNavigationShell` 增加可空 `previousPrimaryIndex`：仅在有效四入口模式中，从其他主 Tab 进入索引 2 时记录来源；重复选择索引 2 不覆盖来源。歌曲页无多选、无上层弹层时，系统返回优先回到有效来源，来源缺失则回首页，且消费此次返回，不触发退出。

用户从歌曲页主动点击其他 Tab 时，清除此临时记录；之后系统返回沿用当前规则：非首页回首页，首页走既有返回/退出逻辑。这不是完整 Tab 浏览历史。多选取消、模态关闭与二级路由返回仍优先于隐藏 Tab 回退。样式切换、C1 尺寸回退至 C3、退出四入口模式时清理临时记录，避免过期回跳。

### 14.2 C2 分体命中

完整包络用于布局留白，不等于整个包络拦截点击。根节点采用只对可交互子节点命中的 Stack；曲名/控制浮标、凸起唱片、左右导航分别拥有明确命中矩形，透明空隙没有可命中的背景、Material、全幅 GestureDetector 或不必要的语义容器。不能给根节点设置 opaque 后吞掉空隙点击。

`HitTestBehavior.translucent` 本身不能保证当前 Stack 会继续检查后面的兄弟节点，因此不能单靠该参数实现穿透。若未来使用自定义 RenderBox，则空隙的 hitTest 必须返回 false。新增 widget 测试：点击上方两侧空隙能触发底层歌曲项，点击凸起唱片只能打开抽屉，点击实体导航不穿透。该命中测试属于阶段二/三。

### 14.3 可见性与 Ticker

阶段二的 `BottomChromeScope.isVisible` 必须综合当前路由是否被完全覆盖、当前主页面、App 生命周期、模态抽屉/队列、隐藏能力及布局模式。黑胶旋转仅在“可见且播放且允许动态效果”时运行，其余情况显式 stop 并保存角度，恢复时从保存角度继续，不能 reset。

共享宿主通过现有路由可见性机制或 RouteAware 接入（包含二级路由覆盖与返回），通过生命周期观察者接入后台状态，dispose 时移除监听。仅依赖 IndexedStack、Opacity 或播放状态不足以保证停止。模态打开时底栏停止旋转，抽屉里的唱片按自己的可见性运行。后续验证活动 ticker 数和隐藏期间角度不变。

### 14.4 抽屉关闭后导航

抽屉操作增加一次性动作结果和 `_isNavigatingToFullPlayer` 等防重入状态；所有前往队列/完整播放页的操作共享互斥锁。记录宿主 Navigator、有效宿主 context 和抽屉的 TransitionRoute，在关闭前取得引用，关闭后不再读取 sheetContext。

`Navigator.pop()` 返回 void，不能调用 `.then()`；`showModalBottomSheet`/`Navigator.push` 返回的结果 Future 通常在 pop 时完成，早于退出动画结束。真正需要等待退出动画和 overlay 清理时，使用抽屉 `TransitionRoute.completed`，不能用固定 250ms 延迟模拟完成。建议由宿主接收 sheet 的操作结果，再等待捕获的 ModalBottomSheetRoute.completed，检查宿主仍 mounted、应用路由条件仍允许后执行一次 push；锁在 try/finally 中复位。快速连点、拖动关闭、系统返回和路由被移除均需覆盖测试。

### 14.5 阶段一落地说明

现有 `AppOnboardingSettings` 明确允许旧版用户引导未完成，因此 `isFirstLaunchSession` 不能直接等同新安装。为优先保护旧用户，在 portable 数据目录重定向之后、任何启动服务写入偏好之前执行 `BottomIslandSettings.ensureLoaded()`：

- 已有样式键：读取稳定字符串；未知类型/值使用 legacy，不覆盖原始值。
- 无样式键且偏好库为空：写入 c1，再发布 notifier。
- 无样式键且已有任何偏好：保守视为既有安装，写入 legacy，再发布 notifier。
- 加载或初始化写入失败：显示 legacy，记录 debug 错误，允许后续重试；显式 setter 失败以 Future 错误交给后续设置 UI 提示，不冒充保存成功。

清除应用数据等同新安装；仅凭偏好无法区分完全无数据的旧安装与新安装，该信息限制接受为空库 C1 的边界。反之，带恢复偏好或残留偏好的安装保守保留 legacy。

阶段一布局模型包含有效样式、稳定目的地索引、导航/播放区显示能力、安全区、键盘显隐、字体缩放与样式切换最大包络；不负责渲染和命中检测。C2 预留曲名及独立播放控制行，实际包络会大于原型主体的 60dp。当前布局数值是后续 UI 共用的起点，实际几何调整必须同步更新模型与验收。

## 20. 简化手机播放入口与 C2 布局
